# V2 专项场景开发与验证（2026-11-05）

原十四人场景保留作为回归对照。新增三个入口将免疫、静态障碍响应和玩闹者提前置于观察中心，不必等待十四人自动演示后半段。好奇—恐惧双 SIS、好奇行为、心理视野、近距离保护和运动上限均不改变。

## 设计

- **免疫专项**：1 台机器人、1 名 `immune_dynamic` 行人，机器人往返通过其四目标循环路线附近。心理量始终为零、模式始终 REGULAR；仍会出现物理动态避让，不是无视碰撞。
- **静态障碍响应专项**：与免疫专项使用相同位置、路线、种子和机器人任务，唯一类型变化为 `impassive_static`。机器人当前位置圆形包络产生静态排斥，机器人移动仍更新包络位置，但不使用速度预测。不是让行人站着不动。动态/静态差异应看力诊断及配对轨迹，不能仅凭 REGULAR 标签判断。
- **玩闹专项**：1 台机器人先后访问两个相隔 10 米的互动区，13、14 号均偏好 robot_1。采用现有角色，保留四点循环任务。脚本只发送 Nav2 目标，不设置心理量、模式或行为触发时刻。使用 DWB 闭环观察挡路后的减速/绕行；本专项不继承 SCARED 的高速外部逼近。

原默认占位 2 秒，且机器人停下即开始让开。新参数 `playful_hold_when_stopped` 默认为 0，只有玩闹专项为 1：**已到达前方占位点后**，机器人停下时可以原地观察，仍使用原占位起始时间。正在前往占位点时机器人停下仍中止。占位不追逐、不向机器人身体靠近；风险升高、个人目标记忆失效、运动方向明显改变、邻人冲突仍退出。

玩闹专项机器人限速 0.10 m/s，前向净距基项从 1.0 m 调至 1.5 m、拦截限时从 4 秒调至 6 秒，为停稳与身体转向留出空间；不是扩大心理视野。专项低速判定为0.02m/s（原场景0.05m/s），真正停车仍中止未到位的拦截。占位最多 8 秒，每人最多 3 次尝试，退出后至少冷却 8 秒并完成受保护任务回归，再满足原来的连续 CURIOUS、好奇、恐惧、风险、可见性与前方可达条件才允许下一次。**上限不是触发保证**，新奇度衰减后可能无法再次触发。不能通过强行维持高好奇或延长 THREATENING 标签制造演示。让开阶段虽然沿用 THREATENING 标签，报告必须将真正的 `occupy` 与 `yield` 分开。

这些时间和次数是未拟合的展示条件，不能推断真实儿童必然长时间或反复挡路。真实儿童的持续互动倾向仍需独立数据验证。

## 启动

在工作空间根目录运行，每次先结束上一轮。

```bash
# 免疫：动态避让，心理不响应
./scripts/run_multirobot.sh config/scenarios/one_robot_multi_sfm_1_immune_v2_nav2.yaml auto_demo:=true crowd_viz:=true isaac_overlay:=true viz_focus_id:=1
# 静态障碍响应：与免疫专项配对比较
./scripts/run_multirobot.sh config/scenarios/one_robot_multi_sfm_1_static_v2_nav2.yaml auto_demo:=true crowd_viz:=true isaac_overlay:=true viz_focus_id:=1
# 两名玩闹者先后互动：先看13号，再看14号
./scripts/run_multirobot.sh config/scenarios/one_robot_multi_sfm_2_playful_v2_nav2.yaml auto_demo:=true crowd_viz:=true isaac_overlay:=true viz_focus_id:=13
```

去掉 `auto_demo:=true` 即为人工发送导航目标；可将 `viz_focus_id` 改为 14。两个玩闹者都只对同一台机器人互动，通过空间访问顺序错峰，不是按时间强制切换模式。

## 验证记录

证据保存在 `evidence/v2_specialists_20261105/`，高频运行数据在 `evidence/runs/v2_specialists_20261105/`。实际结果在完成验证后追加；场景配置本身不代表行为已经通过验收。

首轮 `playful_01`（a84d551）：13号自然进入占位，但2.375秒后因身体仍在运动、未能及时转回而丢失个人目标记忆。人工提前结束该失败试验，驱动记录 KeyboardInterrupt 并清理其进程；没有完整实际验收报告，原始轨迹保留。修改仅为专项前方距离1.5米、拦截上限6秒、机器人限速0.10m/s。随后单人切片 C++ 闭环 `playful_cpu_02` 完成8秒前方占位、主动让开和任务回归；这属于规定机器人运动的核心验证，不能代替 Isaac/Nav2 实际验证。

第二轮实际运行的在线记录已观察到：13号在仿真12.125秒开始互动，13.725～21.725秒处于占位阶段；14号在178.500秒开始互动，183.650～191.650秒占位。两人分别完成让开和任务回归，每人一次，不强行用完3次上限。以上为提交状态时序；实际角色占位时长、净距和完整导航结果以最终验收报告为准。实际导航会绕行，故第二次互动可能发生在机器人驶入第二个区域的途中，不要求恰好到达预设导航节点才触发。

第二轮 `playful_02` 的实际角色前方占位为13号8.000秒、14号8.000秒，最小人机净距0.265米，最大显示误差0.086米；但在第334.425秒仿真时出现健康消息超过0.6秒未到达，验收中止，剩余导航未完成，**整轮判失败**。最后状态仍为healthy、无核心fault，当前只能定位为健康消息接收时序超限，不能宣称原因已修复。失败报告和完整轨迹保留，不放宽健康阈值。

为让专项在目标行为完成后结束，最终三个专项均只保留两轮导航：免疫/静态为一次通过与返回；玩闹为访问13号区域后前往14号区域。删去的第三、四轮是重复穿行/长距离返航，没有新的专项展示目的。这是展示流程收敛，不是健康时序问题的修复；后续验收仍使用相同0.6秒健康门槛，并报告实际运行长度，不作长时间稳定性结论。

观察另一名行人的刺激箭头时，可在已经加载相同 ROS 环境与 ROS_DOMAIN_ID 的另一个终端执行 `ros2 param set /crowd_visualizer focus_id 14`；该参数只调整可视化关注对象，不改变心理或行为。Isaac 的所有角色模式标签仍保留。

第三轮 `playful_03`（两轮导航）完成了全部导航，健康与几何检查通过，13号实际占位8秒；14号拦截途中在机器人速度0.04737m/s时被原0.05m/s低速判定中止，因此缺少占位，整轮专项验收失败。该瞬间机器人仍可见，速度先逐步从0.08421下降至0.04737m/s，行人让开后机器人恢复到0.10m/s。这是低速行驶被归为停止，不能改写为成功挡路。拟仅在玩闹专项将 `playful_min_robot_speed` 改为0.02m/s；该值仍是待标定运动判定，真正停下以及风险升高仍退出。

静态专项 `static_01`：完整两轮导航通过，墙钟120.047秒、仿真108.425秒，最小人机净距0.264米，最大显示误差0.064米。免疫专项 `immune_01`：仿真74.475秒发生健康超时与机器人保护停车，整轮失败，最小净距0.217米；时序记录在中断附近有 `/clock` 与里程计约0.643秒间隔，最后心理核心状态没有fault。不能把该失败解释为免疫类型产生恐惧。两轮报告均保留。

重跑前宿主读取显示GPU 1当前较忙，选择负载较低的GPU 0执行后续验证，GPU状态另存证据。该读数不能追溯证明先前失败的根因。实际展示验收与长期时序稳定性分开记录。

GPU0免疫重跑 `immune_02` 仍在仿真19.8秒出现健康超时；同一时刻时序记录显示 `/clock` 约0.789秒间隔。心理量始终为零、最小净距0.217米，但整体未通过。换GPU并未消除问题，不能宣称资源原因或修复已得到证实。

## 最新验收口径（用户修正）

本节优先于上述历史运行的0.10米门槛描述。后续V2与SCARED实际反应验收默认将人机净距作为导航交互结果记录，低净距/圆形包络重叠不单独判人群模型失败、不据此提前中止。细节与数据语义见 [CROWD_RESPONSE_ACCEPTANCE_20261105.md](CROWD_RESPONSE_ACCEPTANCE_20261105.md)。历史报告保持旧strict结果，健康/同步错误仍独立保留。
