# 人群反应验收与导航交互结果分离（2026-11-05）

依据本次开发中用户的修正：平台首先用于研究人群如何响应机器人，不能因为导航算法造成低净距就提前丢弃该次实验。低净距、接近、避让和接触附近的片段正是后续导航算法需要评估的数据。

## 新规则 `crowd_response_v2.1`

| 维度 | 处理 |
|---|---|
| 实际人机净距 < 0.10m | 记录，不单独使模型验收失败，不提前结束观测 |
| 人机圆形包络净距 < 0 | 记录包络重叠，继续观察；不能仅凭包络认定真实网格发生接触 |
| 惊讶/恐惧/好奇/玩闹响应 | 根据刺激、个体类型和进入/退出条件检查；免疫者不响应也是正确结果 |
| 展示覆盖 | 例如专项预期两人完成占位，未覆盖则该次展示不通过；不等于模型方程一定错误 |
| 无效数值、状态与显示不一致、事务/时钟错误、丢失健康数据 | 仍判执行/数据质量错误；记录并保留试验 |
| 人际/墙体几何、运动执行边界 | 仍按原模型执行契约检查，不因人机参考净距改为记录而取消 |

“通过”仍表示指定实验的执行与展示要求通过，不是对真实人类心理的科学验证。人机近距本身既不能证明模型失败，也不能证明反应合理。实际响应应联系接近速度、持续时间、可见性、风险估计、类型和状态转换分析；不强制每次近距都出现 SCARED。

0.10m 只是兼容历史数据的工程统计参考线，不是已辨识的心理不适阈值，也不是所有导航算法统一的安全边界。

## 实现及数据

`validate_psychology_v2_experiment.py`、`validate_psychology_v2_runtime.py` 和 `validate_scared_stimulus_runtime.py` 默认使用 `--robot-clearance-policy record`。人工启动场景的命令不变。用 `--robot-clearance-policy strict` 可重现旧0.10m验收门槛。通用旧版 `validate_multi_sfm_runtime.py` 的默认strict保持兼容。

报告新增 `acceptance_version` 和 `navigation_interaction`，按行人—机器人对记录：最小净距、低于参考线/包络重叠的采样数、片段起止、观测时长、缺测间隔与截断标志。同时输出 `acceptance.clearance.jsonl`（文件前缀跟随 `--output`），保留**全部匹配样本**，包含角色实际位置、插值到同一时间戳的机器人位置和净距。与原 `acceptance.actual.jsonl`、心理日志、源码与参数清单按时间关联，保留触发、未触发、近距后的恢复和不响应片段。

时长只累加连续低于阈值的相邻观测端点；不猜测阈值穿越时刻，不跨超过0.25秒的缺测拼接，因此是有观测支持的时长下界。0.25秒是统计连续性设置，不是放宽控制/感知超时。

## 与控制约束的区别

本次调整的是**观察和验收策略**，没有改变核心人机排斥、硬速度/加速度上限或健康停车。对危险机器人轨迹，行人仍按现有物理与心理机制响应，不通过删除物理保护制造碰撞。

SCARED 自动外部速度刺激协议自身仍有0.18m停止条件；该条件与0.10m验收参考线不是一回事。这次未同时修改刺激控制器。因此，原自动协议仍是有界刺激，不是持续碰撞试验。后续接入自己的导航算法时，去掉 `auto_demo:=true`，通过该外部控制场景的 `/robot_1/cmd_vel_external` 输入算法输出，再用record策略记录结果。导航指令、机器人实际轨迹、行人反应及输入有效性应分别保存。

## 版本与证据

此前所有GPU验证报告使用旧strict策略，保持原始结果，不重新覆写为“通过”。新增合成观测与真实探针代码路径测试覆盖低净距、负净距及后续恢复，strict回归、缺测不虚构时长、重复时间戳及非法输入检查。没有为了演示这次验收规则而人为制造新的实际碰撞。

免疫专项此前的失败为健康消息超时，最小净距并没有违反旧门槛，所以不能借新规则把它改判成功。玩闹和静态专项完整通过的原始报告仍可用，其有限运行范围不等于长期稳定性结论。
